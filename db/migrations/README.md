# Migrations

Hand-written `.sql` files. Never autogenerated.

The runner in `db/migrations.py` applies files in filename order. The
`applied_migrations` ledger table records which files have been run, so
re-running the script is a no-op.

To add a new migration:

1. Pick the next sequence number, e.g. `0002_add_<thing>.sql`.
2. Write the SQL by hand. Use `IF NOT EXISTS` on every CREATE so
   re-running on a partially-migrated DB is safe.
3. Apply locally via `python scripts/init_db.py`.
4. Commit. On the next deploy, the Dockerfile `CMD` runs init_db before
   exec'ing gunicorn, so the migration applies automatically.

Never edit a migration file after it has shipped. Add a new one instead.
